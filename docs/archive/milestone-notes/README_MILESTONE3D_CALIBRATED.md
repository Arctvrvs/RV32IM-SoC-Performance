# Milestone 3D — calibrated JAL/JALR redirect model

Directed VCS characterization established two independent rules for the current RTL:

1. Every `JAL`/`JALR` has a 2-cycle EX-stage redirect penalty.
2. Before the redirect takes effect, IF issues the two younger sequential requests at `PC+4` and `PC+8`, then restarts at the architectural target.

The second rule is important for backward jumps and call/return traffic because the target stream is a **new cache access stream**, not a retired-PC shortcut. Direct-mapped conflicts can therefore create new misses.

Measured/calibrated targets with a 4-line I-cache and memory latency 3:

| Workload | Cycles | I$ accesses | Hits | Misses |
|---|---:|---:|---:|---:|
| jal_forward_link | 58 | 9 | 2 | 7 |
| jal_backward_loop | 78 | 15 | 6 | 9 |
| jalr_forward | 66 | 10 | 2 | 8 |
| call_return | 107 | 16 | 3 | 13 |

Run after extracting the real VCS results at the project root:

```bash
python scripts/run_milestone3d.py --require-rtl
```

No aggregate-cycle correction constants are used. Extra cycles arise from the 2-cycle redirect penalty and cache misses generated by the explicit IF request stream.
